01 · 报告概览

智能体从"对话工具"演进为"业务参与者"，正在重构企业软件的交互范式

核心趋势

2024–2026 年，AI Agent 的发展已从单轮问答对话进入深度业务融合阶段。市场上形成了两条清晰的演进路径：

  • 从"外挂工具"到"内生节点"：早期 Agent 以独立聊天窗口存在（如 ChatGPT），用户需手动复制粘贴信息；当前主流方案将 Agent 直接嵌入业务流程节点，Agent 可读取上下文、调用业务接口、自动执行操作。
  • 从"单点辅助"到"全流程编排"：从单次问答辅助，进化为多 Agent 协作编排，覆盖"理解→规划→执行→校验→反馈"完整闭环。
关键判断

Agent 不再是业务系统的"插件"，而是业务系统的"第二操作系统"——它直接驱动业务流转，而非仅提供信息参考。能否将 Agent 无缝编入审批流、数据流、操作流，是下一代企业平台的分水岭。

3.2 内嵌操作面板（Embedded Panel）

3.4 工作流节点 Agent（Workflow Node）

Agent 作为审批流程中的一个自动节点嵌入。流程流转到该节点时，Agent 自动执行任务（如摘要生成、风险预测、合规校验），生成结果后流程继续。代表产品：光粒流程Agent审批助手、ServiceNow Now Assist。

核心优势

  • 混合编排：Agent节点和人工节点自由组合，灵活编排复杂流程

3.5 智能推荐与自动补全（Inline AI）

Agent 隐藏在业务表单和输入框背后，在用户填写时实时给出智能建议。如自动补全合同条款、推荐审批意见、智能填表。代表产品：Microsoft Dynamics Copilot、Notion AI。

  • Agent = 流程节点：Now Assist 的核心价值在于Agent嵌入Workflow而非独立存在——这是最接近光粒平台流程Agent的模式
  • 知识库驱动：Agent基于ServiceNow Knowledge Base回答，避免幻觉
  • 操作可追溯：Agent执行的所有操作记录在流程实例中，审计可查

06 · 对光粒平台的落地建议

基于市场调研，给出光粒平台 Agent 融合业务的产品演进路径

核心建议：Agent 融合的三层架构

L1
交互层

提供多种Agent入口形态，适配不同业务场景

  • 侧边栏Copilot（审批/合同场景）
  • 浮动AI助手（全局场景）
  • 对话主界面（智能体中心）
  • 内嵌面板（数据分析场景）
L2
编排层

将Agent编入业务流程，实现流程级融合

  • 流程设计画布 + Agent节点
  • Agent节点绑定智能体中心Agent
  • Agent结果写入流程变量
  • 人工节点 + Agent节点混合编排
L3
能力层

智能体中心提供Agent能力供给

  • 智能体管理（增删改查+编排）
  • MCP管理（工具/API调用）
  • SKILL管理（技能配置）
  • 知识库管理（RAG向量化）

分阶段落地路径

阶段目标关键动作
V1.0 当前 Agent能力供给 + 流程编排基础 智能体中心（Agent/MCP/Skill/知识库管理）、流程中心（流程设计画布+Agent节点）、应用中心
V1.5 近期 Agent融入业务交互 在工作台页面接入侧边栏Copilot和浮动AI助手；Agent可读取页面上下文并建议操作；审批流中Agent节点可实际执行
V2.0 中期 Agent深度融入业务流程 Agent可直接写入业务系统（CRM/ERP）；多Agent协作处理跨部门流程；Agent审批助手覆盖全审批场景；数据分析Agent支持自然语言查询
V3.0 远期 Agent驱动的自主业务 数智员工（自主Agent）承担重复性业务；圆桌会议多Agent推演辅助决策；Agent编排可视化覆盖全业务流程
⚠️ 关键风险提示
  • 可控性：Agent自动操作必须有权限校验+操作日志+人工确认环节，不能让Agent无约束地修改业务数据
  • 幻觉控制：Agent建议应基于知识库/数据（RAG），而非纯生成；高风险结论必须标注来源
  • 渐进式：从"建议优先"（人决定）到"自动执行"（Agent决定）分步推进，先积累信任
